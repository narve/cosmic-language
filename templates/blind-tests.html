Blind Tests

Can a reader who gets nothing but the bits work out what the message says, and why it was sent? This page records what happened when a language model was given only the bit stream. The results are encouraging and they are also thin: four runs, one kind of reader. Read the caveats before drawing conclusions.

1. The setup

The reader is a language model started with no knowledge of this project: no files, no instructions, no settings, no network, in an empty directory. It gets a short task text and the message as a stream of 0s and 1s. The task text describes the situation and what to report. It contains none of the project's vocabulary: no "token", "chunk" or "prime", and nothing about games or peace.

There are two settings:

No tools
The bits are part of the prompt, and the reader can only read and reason.
A code tool
The reader can run Python inside a sealed container that has no network and holds a single file, the bits. This is closer to a real receiver, who would certainly have a computer.

And two tasks:

Last statement
"Work out the meaning of the last statement in the message." The reader has to find out for itself what a statement is.
Purpose
The bits are presented as an artificial radio signal from outside the solar system, sender unknown. "Work out why this message was sent. What does the sender want the receiver to understand, believe or do?" The reader must also give other explanations and say what the message leaves out.

3. What the last statement means

Without tools (run 1)

Reading 176,000 bits by eye, the reader found the beacon and the terminator, the 16-bit tokens, calibration and counting, the split into a type and a value, the brackets, and = from the first sentences. It worked out that a statement is a top-level bracket group. It read the inner equation of the last statement correctly, token for token, as numbers:

(= (67 (19 (63 66) a b c)) (66 (67 a) (67 b) (67 c)))

It did not get further. It never looked at the three quantifiers around the equation, and it could not search the message for where the four symbols are introduced. Its guess at the meaning, a De Morgan law, was wrong, and it said itself that the guess was speculation.

With a code tool (runs 2 and 3)

With Python, the reader decoded the whole message and explained every symbol of the last statement from the sentences that introduce it. In run 3, after the message had been reordered to end with the prisoner's dilemma, its rendering of the last statement was:

( ∀ v1 ∈ SIX
   ( ⇒ ( ≠ v1 TFT )
       ( > ( fold + ( map v2 SIX ( score TFT v2 10 ) ) )
           ( fold + ( map v2 SIX ( score v1  v2 10 ) ) ) ) ) )

The names are the reader's own labels; it only ever saw numbers. In its words:

For every one of the six listed strategies other than the "cooperate first, then copy the opponent's previous move" strategy, that strategy's total payoff is strictly greater than theirs. The total is summed over 10-round games against all six strategies, including itself: it scores 154 against 147, 143, 142, 128 and 113.

Two things stand out. The reader named the sentence that taught it "for all": the one that sets a statement about every item of the list 1, 2, 3 equal to the and of its three instances. And without being asked, it wrote its own simulation of the six strategies from the message's definitions and reproduced all 18 scores and totals the message states.

4. Why the message was sent (run 4)

Asked for the purpose, the reader decoded all parts of the message. It identified the electron, proton and neutron from their mass ratios, the fine-structure constant, the Planck units, the 21 cm line of hydrogen, and the four bases of DNA from their formulas. Its conclusion:

The message is an opening move plus a statement of policy. It reads as: "We know contact is a repeated dilemma. We know defection can win a single encounter. Here is a checkable reason why we reciprocate — cooperate first, answer in kind — and why you should too." What it wants from the receiver is a cooperative reply, and an understanding that cooperation will be returned and defection also returned.

How it read the design:

  • The mathematics is scaffolding. Lists hold the history of a game, if and the quantifiers define strategies, apply and sequence add up scores, mean and chance handle the strategies that pick at random.
  • The physics is proof of honesty and competence. The receiver can check 1836, 1/137 and the ratios in the spectrum of hydrogen for itself.
  • observed marks a line between what must be believed on evidence and what can be checked by calculation. The results of the game are of the second kind.
  • The transmission is itself a cooperative move: free, true information, sent unprompted.

It gave this reading about 60 %, and weighed three others:

Other readingIts weightIts main argument against
A deterrent: "we retaliate"15 %The comparisons the message stresses are cooperation over defection, and it shows no threats or capabilities.
A primer or beacon: "we are here, this is what we know"15 %The science stops without astronomy or any description of the sender, and the ending is not science.
Manipulation into cooperating, or something else10 %The message recommends conditional cooperation, which cannot be exploited much. But "the message cannot rule this out".

The reader called these numbers judgement, not measurement.

5. What the reader could not find

These are the most useful results: each is something the message does not yet say, or says badly.

  • No "us" and no "you". Nothing says that the sender plays tit-for-tat, or that the game is about sender and receiver. The reading "a statement of policy" is the reader's inference. The message is meant to say "we come in peace"; so far it proves that peace wins a game.
  • No request. There is no question, no instruction and no channel for a reply.
  • Nothing about the sender: no place, no time, no body, no history. (Whether to say where the message comes from is a deliberate open question, see the specification.)
  • No stakes. Nothing says what cooperating or defecting would be in practice.
  • A narrow result. The theorem holds for six strategies and ten rounds. It is an illustration, not a general proof.
  • Water's temperature is ambiguous. The bounds the message gives allow roughly 230 to 460 K, so the reader could not tell which temperature of water is meant.
  • The rational numbers were read as the integers. What the message says about ℚ did not set it clearly apart.
  • From run 2: the domain expressions is never shown by example; nothing that is sent says that if computes only the branch it picks; and there are no rules for evaluating ∀, ∃ and sequence.

6. Caveats

  • The reader is not an alien. It is a model trained on human writing. It knows prefix notation, the prisoner's dilemma and what tit-for-tat is taken to mean, and it knows the masses of the particles. A real receiver shares none of that. These tests show that the message is consistent and can be decoded by a mind with human mathematics. They do not show that it can be decoded by a mind without it.
  • Few runs. One run per setting. A second run could go differently.
  • The runs cannot be compared with each other. Runs 1 and 2 differ in the tools, in the model and in the message at the same time, so they do not show which change helped.
  • The reader skipped what it did not need. For the last statement it passed over physics and chemistry. Only run 4 looked at them, and briefly.
  • The reader made mistakes that did not affect its conclusions: a wrong count of tokens in one place, and the integers for the rationals.
  • The task text is part of the experiment. Run 4 was told that the signal is artificial, that it is a message and that it was sent for a reason. A real receiver has to reach that by itself.
  • The message is a draft. It has changed since these runs and will change again.

7. Running the tests again

The task texts, the tool and the reader's full answers, with the code it ran, are in build/check/blind/ in the repository. After npm run build:

npm run --silent blind:prompt
Prints the task and the bits, to give to any reader, model or person.
npm run --silent blind
The last-statement task, without tools.
npm run --silent blind:code
The last-statement task with the code tool. Needs Docker.
npm run --silent blind:code purpose-code
The purpose task with the code tool.
