Until now, every sentence in the message has been asserted: written down, it claims to be true. The next lessons let the message mention a sentence without claiming it, take sentences apart like lists, and compute their values. The last of them is eval, the value of any expression, written in a few sentences of the message itself. This is the idea at the heart of Lisp, published by John McCarthy in 1960, and the first step towards a message that can describe itself.

(quote S) is the expression S itself, not its value: nothing inside it is computed or claimed. A quoted expression in brackets is a list of its parts, so everything from the lesson on lists works on it. 


; a quoted expression is a list of its parts, so everything that
; works on lists works on it: its length, the rest of it …
(= (quote (+ 2 3)) (list (quote +) 2 3))
(= (length (quote (+ 2 3))) 3)
(= (rest (quote (+ 2 3))) (list 2 3))

; … and its items
(= (item (quote (+ 2 3)) 1) (quote +))
(= (item (quote (+ 2 3)) 2) 2)
(= (item (quote (+ 2 3)) 3) 3)

; a symbol can be quoted on its own
(= (quote +) (quote +))
(≠ (quote +) (quote ×))

; numbers are their own quotes
(= (quote 5) 5)

; an expression is not its value, and two expressions with the same
; value are still different
(= (+ 2 3) 5)
(≠ (quote (+ 2 3)) 5)

(= (+ 2 3) (+ 3 2))
(≠ (quote (+ 2 3)) (quote (+ 3 2)))

; quoted expressions can be nested
(= (item (quote (= (+ 2 3) 5)) 2) (quote (+ 2 3)))
(= (item (quote (quote 7)) 1) (quote quote))

Because a quoted sentence is only mentioned, it may be false. This is the first time a false relation is written out in the message, and it is never asserted: 


; the sentence "2 = 3", taken apart
(= (length (quote (= 2 3))) 3)
(= (item (quote (= 2 3)) 1) (quote =))
(= (item (quote (= 2 3)) 3) 3)
(≠ (quote (= 2 3)) (quote (= 3 3)))

type tells what kind of thing a part of an expression is. Its values are the token types the message has used from the start, the first chunk of every token: 0 for a number, 2 for an operator, 3 for a constant, and so on. A list in brackets has type 1, the type of the brackets. In this text the types are written by name (number, brackets, operator, constant, variable for 0 to 4), but what is sent is the number: (= (type 5) number) is sent as (= (type 5) 0). Later lessons bring new kinds of token (particles, elements, dimensions, physical constants, molecules), and each states the type of its tokens in the same way. 


; the type of a number is 0, of a list 1, of an operator 2, of a
; constant 3, of a variable 4
(= (type 5) number)
(= (type (quote (+ 2 3))) brackets)
(= (type (quote +)) operator)
(= (type (quote true)) constant)

(= (type (quote u)) variable)
(= (type (list 1 2)) brackets)

; an operator in a quoted expression is a symbol like any other
(= (type (item (quote (+ 2 3)) 1)) operator)
(= (type (item (quote (+ 2 3)) 2)) number)

Inside a quote, u is just a symbol of type 4 (variable), not a variable standing for a number.
