The beacon

The first challenge is to mark the signal (which could be e.g. a radio signal) as an actual message, making it stand out in the general noisy universe.

We do this by starting with a sequence of prime numbers, sent as plainly as possible: 1, 2, 3, 5, 7, etc.

Everything is a bit, though, we can't actually send numbers (yet). So we send this in the simplest way - just as a number of 1s, with 0 as a separator:

01011011101111101111111 etc.

A note on active bits

To avoid missing bits being interpreted as 0, we assume active bits - e.g. one frequency is 1, the other frequency is 0. It does not matter which is 0 and which is 1, the message does not change character if we flip every bit. An alternative is Manchester encoding, which is used in e.g. Ethernet (aka "network cables").

A note on primes

Yes, I know, 1 is not normally considered a prime. I've chosen to promote 1 to a prime in this message, since it makes things look nicer, and since we're not going to send any prime number theorems or things like that.

No natural process is known to send the prime numbers in order, so the beacon says that this is artificial. How many primes we send is not significant.

The whole beacon, as it is sent: 174 bits. 


; a 0, then 1, 2, 3, 5 and 7
0 1 0 11 0 111 0 11111 0 1111111 0
; 11, 13 and 17
11111111111 0 1111111111111 0 11111111111111111 0
; 19 and 23
1111111111111111111 0 11111111111111111111111 0
; 29 and 31
11111111111111111111111111111 0 1111111111111111111111111111111 0
