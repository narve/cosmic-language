equal and not equal

Sentences

After the basic numbers, we introduce two new kinds of tokens: brackets and operators.

Type Meaning Value
0 number the number itself, 0 to 255
1 brackets 0 = "(" - open bracket, 1 = ")" - close bracket
2 operator which operator (=, +, …) 

(  00000001 00000000   type 1, value 0: open
=  00000010 00000001   type 2, value 1: the first operator
1  00000000 00000001   type 0: the number 1
1  00000000 00000001   type 0: the number 1
)  00000001 00000001   type 1, value 1: close

With these extra tokens we can build sentences, e.g. (= 1 1).

The operator comes right after the opening bracket, and the rest are its arguments, in what's called Lisp style (or S-expressions). The brackets show where each sentence starts and ends, so the receiver never has to guess how many arguments an operator takes.

Equal

The first operator is =. In every sentence its two arguments are the same number, so the receiver can guess what it means. The numbers are (some of) the primes the receiver already knows from the beacon and the calibration, and then the smallest and the largest number a chunk can hold. 


; each number equals itself: first (some of) the primes of the beacon
(= 1 1)
(= 2 2)
(= 3 3)
(= 5 5)
(= 7 7)
(= 11 11)
(= 13 13)
(= 17 17)

; then the smallest and the largest number of a chunk
(= 0 0)
(= 255 255)

Not equal

After =, we introduce ≠, not equals. We show a few examples, and mix = and ≠ to make it clear what these operators mean. 


; two different numbers are not equal
(≠ 0 1)
(≠ 1 0)
(≠ 2 5)
(≠ 7 3)
(≠ 254 255)

; mixed, to show the contrast
(= 4 4)
(≠ 4 5)
(= 9 9)
(≠ 9 6)

; = can compare more than two: all are equal
(= 3 3 3)
(= 7 7 7 7)
(= 0 0 0 0 0)

= takes two or more arguments and means that all of them are equal. ≠ takes exactly two arguments: with more, it would be unclear whether it means "all different" or "not all equal".
