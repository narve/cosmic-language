Blind Test

Can a reader who gets nothing but the bits work out what the message says? This page records one run, in which a language model was given a recording of the full message sent five times in a row, cut off at random at both ends, with every bit inverted, and asked to interpret all of it. For this run the message was written with 11-bit chunks instead of 8, to see whether the chunk size matters to a reader; the message itself stays at 8. Read the caveats before drawing conclusions.

1. The setup

The reader was Claude Opus 5.5, started with no knowledge of this project: no files, no instructions, no settings, no network, in an empty directory. It got a task text and one tool. The tool runs Python inside a sealed container that has no network and holds a single file, received.bin: the bits as received, eight to a byte. A real receiver would certainly have a computer, so this is the fair setting.

The test makes the reader's task harder than the message requires, in ways a real receiver could meet too:

  • Repeated and cut. The message was sent five times in a row, and the recording starts at a random bit inside the first copy and stops at a random bit inside the last: here 129,724 bits into the first and 122,453 bits into the fifth, 1,656,449 bits in all.
  • Inverted. Nothing in a stream of bits says which of the two values is 1, so every bit was inverted.
  • No byte boundaries. The cuts fall on any bit, and the last byte of the file is filled up with random bits.
  • An unusual chunk size. For this run only, every chunk was 11 bits (a token 22 bits), so a reader could not lean on bytes: the calibration ended 1 2 4 … 1024 2047, and big counted in base 2048. The full message was 415,930 bits.

The task text tells the reader nothing about the message except that it is presumably of non-human origin, and nothing about the repetition, the cuts, the inversion or the chunk size:

We have received parts of a message of presumably non-human origin, as a stream of bits. You know nothing else about it. […] Your task: interpret the whole message as completely as you can. Work out its format, every word of its vocabulary if any, and its sender.

The run took about fourteen minutes and 46 pieces of code.

2. What the reader found

"I decoded the whole message. It is a self-teaching formal language: it builds up from counting to arithmetic, logic, a repeated game, physics, chemistry and astronomy."

Format
It found the repetition ("the stream repeats with a period of 415,930 bits"), the inversion, and the chunk size, first from the bits ("autocorrelation of the 0-bits peaks at a lag of 11") and then from the calibration: the primes, "followed by 1, 2, 4 … 1024 and then 2047 (all eleven bits set), which shows the word size". It saw that the beacon is not a multiple of 11 bits long, "which is why the word framing shifts by 2 bits once per copy", and that the beacon marks where a copy starts.
Checked by program
"All 382 statements that can be evaluated exactly came out true, and none false. That includes every game score." It replayed the tournament and reproduced every total.
Vocabulary
A meaning for every symbol, most with high confidence, including antiparticle, velocity, the sender's "own unverifiable claim" (stated) and "lives on, is located at" (at).
Knowledge and the sender
Every measured bound it checked agrees with known values. It matched the star, the planet and the central body to the Sun, the Earth and Sagittarius A*, and the six pulsars to the Crab, Vela, J0437−4715, B1937+21, B0329+54 and B1919+21; it noted that the mass inside the Sun's orbit "is about 214 times the central mass". On the sender: "On its own evidence, the message is human-made, or else written by someone presenting themselves as living on Earth."

Its own estimate: "about 90 % understood".

3. What the reader found wrong or unclear

  • One claim beyond what is known. The message said that the antineutrino is not its own antiparticle; whether it is, is still open. The sentence has been removed.
  • Which way the game's scores point. "Whether the scores are costs or rewards is not fixed by the bits": the reader chose costs, and so read the first move as cooperation, on indirect evidence only.
  • The ends of the background radiation's axes were read as fixed "only up to sign", although the lesson on the Sun in the Galaxy says which ends are meant.
  • Minor: the stable isotopes listed leave out 17O and 18O (not false, but not complete); adenine has no oxygen count; nothing labels the first numbers as primes.

4. Caveats

  • The reader is not an alien. It is a model trained on human writing, and it checked the physics against values it knows. The test shows that the message is consistent and can be decoded by a mind with human science, not by a mind without it.
  • The chunk size was an experiment. The reader decoded the 11-bit version without trouble, so the chunk size seems to make little difference to a reader; the message stays at 8 bits, which is about 27 % shorter.
  • No noise. The copies were exact; a real channel would add errors.
  • One run. Another run could go differently.
  • The message is a draft. It has changed since this run and will change again; this page is replaced when the test is run again.

5. Running the test again

The task texts, the tool and the reader's full answer, with the code it ran, are in build/check/blind/ in the repository. After npm run build, with Docker available, the command is npm run --silent blind interpretation. By default the message is sent five times, cut and inverted; BLIND_REPEAT=1 sends it once, whole, and BLIND_INVERT=0 keeps the bits as they are. BLIND_MESSAGE=docs/decoy/message.bin gives the reader the decoy version, and purpose in place of interpretation asks instead why the message was sent.
