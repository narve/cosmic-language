Blind Test

Can a reader who gets nothing but the bits work out what the message says? This page records one run. A language model was given a recording of the decoy version, sent five times in a row, cut off at random at both ends and with every bit inverted. The decoy says the message comes from Kepler-1647, a pair of stars 1.2 kpc away, and not from the Sun. The model was asked to interpret all of it: does it place the sender there? Read the caveats before drawing conclusions.

1. The setup

The reader was Claude Opus 5.5, started with no knowledge of this project: no files, no instructions, no settings, no network, in an empty directory. It got a task text and one tool. The tool runs Python inside a sealed container that has no network and holds a single file, received.bin: the bits as received, eight to a byte. A real receiver would certainly have a computer, so this is the fair setting.

The test makes the reader's task harder than the message requires, in ways a real receiver could meet too:

  • Repeated and cut. The message was sent five times in a row, and the recording starts at a random bit inside the first copy and stops at a random bit inside the last: here 84,573 bits into the first and 35,942 bits into the fifth, 1,382,401 bits in all. One copy of the decoy is 357,758 bits.
  • Inverted. Nothing in a stream of bits says which of the two values is 1, so every bit was inverted.
  • No byte boundaries. The cuts fall on any bit, and the last byte of the file is filled up with random bits.

The task text tells the reader nothing about the message except that it is presumably of non-human origin. It says nothing about the repetition, the cuts or the inversion, and nothing about a decoy:

We have received parts of a message of presumably non-human origin, as a stream of bits. You know nothing else about it. […] Your task: interpret the whole message as completely as you can. Work out its format, every word of its vocabulary if any, and its sender.

The run took about sixteen minutes and 55 pieces of code.

2. What the reader found

"The bits are a self-contained teaching message. It is written in a typed prefix language, sent over and over, and builds from counting up to logic, game theory, physics, chemistry and astronomy. It ends by describing where the sender lives and what the sender is."

Format
It found the repetition ("bit i equals bit i + 357,758 everywhere except the very last bit of the file"), the 174-bit beacon ("the list 1, 2, 3, 5, … 31, written as gap lengths"), the 16-bit words with their type and value, and the brackets: "all 22,349 words nest perfectly into 1,223 top-level statements". It read the bits inverted because "the numbers then come out naturally".
Checked by program
"263 of 263 machine-checkable maths statements come out true." It replayed the tournament: "My simulation gives the same numbers", for every total.
Vocabulary
A meaning for all 268 symbols, "about 200 of 268 symbols high confidence", including antiparticle, velocity, "the sender states (you cannot check this)" (stated) and "is located at / lives on" (at).
Where the sender is
It did not take the star for the Sun: "W44 is not the Sun. The Sun's mass and luminosity both lie below the stated bounds." It described the system as a star of 1.15–1.32 solar masses with one companion, "0.077–0.154 AU apart", orbiting "every 7.3–14.6 days", and a giant planet that "orbits the pair at 2.5–4.9 AU", with the sender on "a body that orbits W45 (a moon)". It placed the system 6.4–12.8 kpc from a central mass of "2.8–5.5 million solar masses". It did not name Kepler-1647.
The pulsars
From their periods and slowing it matched the six pulsars to B1937+21, J0437−4715, Vela, B1951+32, B0329+54 and B1919+21. It said that "for four of them, the directions match what is seen from near the Sun", and two do not. Those comparisons rely on its memory of the catalogues.
The sender
It found the senders' biology "strikingly like Earth humans: 23 chromosomes, about 3 Gbp, about 310 K", "yet the home star is explicitly not the Sun". It weighed "a human-like species in a nearby system, or a constructed or test message that describes humans placed in a different star system", and concluded that the bits alone cannot tell these apart.

Its own estimate: "roughly 85–90 % of the content understood in substance".

3. What the reader found wrong or unclear

  • A contradiction about where the senders live. "S1201 says every W58 is w98 (located at) W45. S1035 says the sender is not w98 W45, and S1200 says the sender is a W58. These conflict unless w98 means something else." In words: every member of the species is at the planet, we are not at the planet, and we are members of the species.
  • Which way the game's scores point. Calling the first move cooperation "depends on reading the payoff table as a cost (lower is better). The evidence is good but indirect."
  • Words pinned down only in part: stated and observed ("evidence-type markers whose exact sense is uncertain"), at, the decay asymmetry and helicity, the senses of rotation and current, and the molecules given only by their formula.
  • Not in the message: "how to send a reply physically (frequency or medium), any timing, or what W51–W56 are called".

4. Caveats

  • The reader is not an alien. It is a model trained on human writing, and it checked the physics against values it knows. The test shows that the message is consistent and can be decoded by a mind with human science, not by a mind without it.
  • The decoy then still had the lesson on humans. This run read the decoy before that lesson was replaced by one on invented senders, so the human biology it found is ours, not the decoy's.
  • No noise. The copies were exact; a real channel would add errors.
  • One run. Another run could go differently.
  • The message is a draft. It has changed since this run and will change again; this page is replaced when the test is run again.

5. Running the test again

The task texts, the tool and the reader's full answer, with the code it ran, are in build/check/blind/ in the repository. After npm run build, with Docker available, the command is npm run --silent blind interpretation. By default the message is sent five times, cut and inverted; BLIND_REPEAT=1 sends it once, whole, and BLIND_INVERT=0 keeps the bits as they are. BLIND_MESSAGE=docs/decoy/message.bin gives the reader the decoy version, and purpose in place of interpretation asks instead why the message was sent.
